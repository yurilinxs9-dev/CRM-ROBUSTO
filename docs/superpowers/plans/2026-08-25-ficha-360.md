# Ficha 360 do lead — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ficha completa do cliente no visual da proposta Ciafal — badges, linhas de dados, resumo da IA, memória, ÚLTIMA COMPRA (IA extrai da conversa), NOTA DO ATENDIMENTO (0-10 + ponto forte/melhoria) e sugestão em bloco laranja — no Radar (card expande) e no drawer do lead.

**Architecture:** incremento sobre o LeadInsight no ar: 4 colunas novas (SQL manual aditiva), prompt/sanitizador estendidos (TDD), worker persiste com regra de não-regressão da última compra, componente único `Ficha360` consumido pelo drawer (substitui o InsightCard) e pelo Radar (expansão lazy). Spec: `docs/superpowers/specs/2026-08-25-ficha-360-design.md`.

**Tech Stack:** o mesmo do lead-insights (NestJS+Prisma+BullMQ; Next+RQ+shadcn). Jest API para toda lógica; web sem unit (só lib/).

## Global Constraints

- NUNCA `prisma migrate deploy`/`db push` — SQL manual em `apps/api/prisma/manual/`, aplicada via node+Prisma no container ANTES do backend novo (runbook igual às entregas de hoje).
- NUNCA `any`. Jest `--maxWorkers=2`. `tsc --noEmit` nos dois apps; `npm run build` no web.
- Conteúdo vindo de LLM renderiza SEMPRE como texto React puro — nunca `dangerouslySetInnerHTML`.
- `nota_atendimento` avalia o ATENDENTE (rapidez, clareza, condução), nunca o cliente. `ultima_compra` só do que o cliente CITOU (nunca inventar) e nova geração não-null substitui, null NÃO apaga a anterior.
- Sanitização: nota int 0-10 ou null; textos da nota ≤200; ultima_compra `{descricao ≤200, valor number ≥0|null, quando ≤60}` ou null.
- Badges derivados: QUENTE/MUITO_QUENTE → Promissor; `proxima_acao_at` vencida → Chamar hoje; ≥7d sem interação → Esfriando; precedência Chamar hoje > Promissor > Esfriando.
- Branch `feat/ficha-360` de `master`. Commits `feat(api):`/`feat(web):`.
