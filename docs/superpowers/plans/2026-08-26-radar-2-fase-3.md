# Radar 2.0 — Fase 3 (Lembretes temporais — o diferencial) — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** o prompt do insight extrai marcos temporais ditos pelo cliente ("me chama em outubro", "só daqui 2 meses"), grava em tabela `LeadLembrete` com data de aviso, e no dia o Radar mostra o lead COM DESTAQUE e o contexto original, com concluir/adiar/descartar + criação manual na ficha.

**Architecture:** contrato do prompt ganha a 14ª chave `lembretes: [{ motivo, quando }]` (data resolvida pela IA relativa à data da mensagem — as mensagens no prompt já são datadas); worker cria `LeadLembrete` (dedupe + só datas futuras); radar ganha fila `lembretes_hoje`; endpoints de ação (concluir/adiar/descartar) + criação manual; front = seção destacada no Radar + bloco na ficha 360. Spec: `docs/superpowers/specs/2026-08-26-radar-2-design.md` (Fase 3, itens 7-9).

**Tech Stack:** o de sempre (NestJS/Prisma/BullMQ; Next/React Query/shadcn).

## Global Constraints

- NUNCA `any`. Jest `--maxWorkers=2`. tsc verde nos dois apps; `npm run build` no web.
- Migration: NUNCA `prisma migrate deploy`/`db push`. SQL manual idempotente em `apps/api/prisma/manual/`, aplicada no VPS ANTES do backend novo (padrão apply-fase-4.js: statements hardcoded, um por vez). `prisma generate` via `node ../../node_modules/prisma/build/index.js generate`.
- Spec verbatim: "Regras: nunca inventar; só criar quando o cliente deu um marco temporal explícito ou fortemente implícito."
- Lembrete de IA: `quando` SEMPRE data futura (passada/ilegível = descartada no saneamento); horizonte máximo 12 meses (além = clamp em +12 meses); máximo 3 lembretes por geração; máximo 5 PENDENTES origem 'ia' por lead (excedente descartado com log).
- Dedupe: não criar se já existe lembrete PENDENTE do mesmo lead com `avisar_em` no intervalo ±3 dias E motivo normalizado igual (NFD sem acento, lowercase, trim — técnica de `normalizarFato`).
- Visibilidade do radar preservada (`buildVisibilityWhere` na fila nova; teste pool-mode estendido).
- Linguagem humana; conteúdo de LLM sempre texto React puro; normalização defensiva (backend velho sem a fila → seção some, zero crash).
- Branch `feat/radar-2-fase-3` de `master`. Commits `feat(api):`/`feat(web):`.

```sql
BEGIN;

  "id" TEXT NOT NULL,
  "tenant_id" TEXT NOT NULL,

  "status" TEXT NOT NULL DEFAULT 'pendente',

  "updated_at" TIMESTAMP(3) NOT NULL,
  CONSTRAINT "LeadLembrete_pkey" PRIMARY KEY ("id")
);

DO $$
BEGIN
  IF NOT EXISTS (SELECT 1 FROM pg_constraint WHERE conname = 'LeadLembrete_tenant_id_fkey') THEN
    ALTER TABLE "LeadLembrete" ADD CONSTRAINT "LeadLembrete_tenant_id_fkey"

  IF NOT EXISTS (SELECT 1 FROM pg_constraint WHERE conname = 'LeadLembrete_lead_id_fkey') THEN

      FOREIGN KEY ("lead_id") REFERENCES "Lead"("id") ON DELETE CASCADE ON UPDATE CASCADE;
  END IF;
END
$$;

CREATE INDEX IF NOT EXISTS "LeadLembrete_tenant_id_status_avisar_em_idx" ON "LeadLembrete"("tenant_id", "status", "avisar_em");
CREATE INDEX IF NOT EXISTS "LeadLembrete_lead_id_status_idx" ON "LeadLembrete"("lead_id", "status");

COMMIT;
```
