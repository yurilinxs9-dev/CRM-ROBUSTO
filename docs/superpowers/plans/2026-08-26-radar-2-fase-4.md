# Radar 2.0 — Fase 4 (IA que decide: temperatura automática + sugestão de etapa) — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** na geração da ficha a IA também devolve `temperatura_sugerida` (aplicada automaticamente pelo worker quando o toggle do tenant estiver ligado, com registro na timeline) e `etapa_sugerida` (NUNCA aplicada — a ficha mostra "parece pronto para X — mover?" com aceite de 1 clique).

**Architecture:** o contrato do prompt (`insight-prompt.ts`, lib pura) ganha 4 chaves novas; o worker (`gerarInsight`) aplica temperatura (toggle ON) gravando `LeadActivity` + WebSocket, e persiste a sugestão de etapa validada contra as etapas reais do pipeline do lead; 2 endpoints novos (aceitar/recusar etapa) reusam `LeadsService.updateStage` (atividade + WS + cache de graça); front = bloco novo na `ficha-360.tsx` + switch em Ajustes. 1 migration manual (colunas em `LeadInsight` + `Tenant.ia_ajusta_temperatura`).

**Tech Stack:** o de sempre (NestJS/Prisma/BullMQ; Next/React Query/shadcn). Spec: `docs/superpowers/specs/2026-08-26-radar-2-design.md` (Fase 4, itens 10-11).
