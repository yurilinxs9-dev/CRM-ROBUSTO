# Radar 2.0 — Fase 2 (funil do gestor + pós-venda) — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** o Radar ganha o lado gestor: "Onde está o dinheiro" (promissores agrupados por etapa com R$ somado), "Foco do dia" (top 10 por score composto) e "Compraram" (pós-venda com a compra visível). Sem migration, sem LLM novo.

**Architecture:** `RadarItem` ganha `valor_estimado` e `nota_atendimento`; endpoint ganha 2 filas (`melhores`, `compraram`) com score/critério documentados; o front agrupa promissores por etapa client-side e renderiza as 3 experiências novas. Spec: `docs/superpowers/specs/2026-08-26-radar-2-design.md` (Fase 2, itens 4-6).

## Global Constraints

- NUNCA `any`; jest `--maxWorkers=2`; tsc/build verdes; visibilidade via `buildVisibilityWhere` preservada (teste pool-mode estendido às filas novas); linguagem humana; LLM = texto React puro.
- `RadarItem` += `valor_estimado: number | null` (Decimal→number) e `nota_atendimento: number | null` (do insight).
- **Fila `melhores`** (Foco do dia): candidatos = leads de etapa ativa com `lead_insight` não-null, mesma base+visibilidade, `take: RADAR_BUSCA`; score no app, documentado: `score = temperatura(FRIO 0/MORNO 1/QUENTE 2/MUITO_QUENTE 3)*3 + min(valor/1000, 10)*0.5 + (nota ?? 5)*0.3 + recencia(interacao ≤2d: 2, ≤7d: 1, senão 0)`; top 10; SEM dedupe contra as outras filas (é um ranking transversal, o mesmo lead PODE estar em outra fila — documentar); `RadarItem.score` NÃO é exposto (ranking interno, a UI não mostra número de score — anti "cara de IA").
- **Fila `compraram`**: leads com (`estagio.is_won: true` OU `lead_insight.ultima_compra` não-null), qualquer recência, ordenado por `ultima_interacao desc`, cap 30, sem dedupe contra as outras (universo distinto); `RadarItem` += `compra: { descricao: string; valor: number | null; quando: string } | null` (do insight, mesmo shape persistido).
- `resumo` não muda (fase 1 intacta).
- Front: seções novas SEM inchar a página — "Onde está o dinheiro" é um bloco compacto de grupos (etapa, contagem, R$ somado) clicável que expande os cards daquela etapa; "Foco do dia" lista horizontal/vertical de 10 cards compactos; "Compraram" seção colapsável (fechada por padrão) com a compra em destaque ("Comprou: Mesa Requinte · R$ 3.990 · mês passado") e msg de pós-venda (a msg_sugerida da ficha já cobre).
- Busca e seletor de funil da F1 valem para as seções novas; popover "?" em cada seção nova.
- Branch `feat/radar-2-fase-2` de `master`. Commits `feat(api):`/`feat(web):`.
