### Task 2: API — GET /api/dashboard/financeira (TDD)

**Files:**
- Modify: `apps/api/src/modules/dashboard/dashboard.service.ts`, `dashboard.controller.ts`
- Modify: `apps/api/src/modules/pipelines/` (rota de update de stage aceita `probabilidade` — localizar o update existente do stage e estender o Zod: `probabilidade: z.number().int().min(0).max(100).nullable().optional()`)
- Test: `apps/api/src/modules/dashboard/dashboard.service.spec.ts` (padrão do módulo; criar se não existir seguindo os specs irmãos)

**Interfaces:**
- Produces: `GET /api/dashboard/financeira?pipeline_id=<opcional>` → 
```ts
{
  previsao: {
    total_aberto: number;          // soma valor_estimado das etapas abertas (nem won nem lost)
    ponderado: number;             // soma valor*probabilidade/100
    por_etapa: Array<{ stage: { id, nome, cor, ordem }, count: number, total: number, probabilidade: number, ponderado: number }>;
  };
  ganhos: { mes_atual: number; mes_anterior: number; quantidade_mes: number; ticket_medio: number };
  top_oportunidades: Array<{ lead_id: string; nome: string; valor: number; etapa: string; temperatura: string }>;
}
```
- Regras exatas:
  - Probabilidade efetiva: `stage.probabilidade` quando não-null; default por posição entre as etapas ABERTAS ordenadas por `ordem`: `Math.round(((indice + 1) / (totalAbertas + 1)) * 100)` (1 etapa aberta → 50; 3 → 25/50/75). Won/lost ficam FORA de `por_etapa` (won já é ganho, lost é 0).
  - `ganhos`: leads com `estagio.is_won` e `estagio_entered_at` dentro do mês-calendário SP (atual e anterior); `ticket_medio` = mes_atual.total / quantidade (0 quando quantidade 0); valores Decimal→number.
  - `top_oportunidades`: leads de etapa aberta com `valor_estimado` não-null, `orderBy valor_estimado desc`, take 5.
  - `pipeline_id` ausente = pipeline ativo (mesmo fallback do `getFunnel`). Cache Redis `dash:financeira:{tenant}:{pipeline|active}` TTL 60s (padrão `cached()` do service).
  - Rota no controller com os mesmos guards do módulo.

- [ ] **Step 1: Failing tests:** (a) por_etapa exclui won/lost, calcula default de probabilidade por posição (fixture com 3 abertas sem probabilidade → 25/50/75) e respeita probabilidade explícita (fixture com 40 → 40); (b) ponderado = soma valor*prob/100 (Decimal→number); (c) ganhos mês atual vs anterior com boundary SP (lead ganho dia 1º 00:30 SP conta no mês novo; 31 23:30 SP no velho — fake timers); (d) ticket_medio com 0 ganhos → 0 (sem NaN); (e) top 5 ordenado desc, null valor fora; (f) pipeline_id filtra; ausente → pipeline ativo; (g) update de stage grava probabilidade (Zod aceita null p/ voltar ao default; 101 → 400).
- [ ] **Step 2: RED.** **Step 3: Implementar** (mês SP: mesma técnica Intl de `inicioDoDiaLocal` da fase 3 — duplicação local pequena e documentada OU import dos helpers exportados de `lead-insights.service` — escolher import se não criar ciclo de módulo; senão duplicar com comentário). **Step 4: GREEN** (`npx jest dashboard pipelines --maxWorkers=2` + tsc).
